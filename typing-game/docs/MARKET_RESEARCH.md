調査日:2026年8月30日。
調査方法:Web検索およびGitHub公開リポジトリの参照。公式サイト(magicalmirai.com / developer.textalive.jp / blog.piapro.net)は調査環境のネットワーク制約で直接閲覧できていないため、**一次資料による裏取りが未了の項目には「要確認」を付す**。応募前に公式サイトで再確認すること。

## 1. 結論(先に要点)

1. **同一アイデアの入選作品が既に存在する。** 2023年入選作品『**Typing Lyrics**』(作者:Rozelin)は「楽曲の歌唱に合わせて歌詞をタイピングする」ゲームで、本企画のコアと重なる。React + TypeScript + TextAlive App API という技術構成まで一致している。
2. ただし **最優秀賞・優秀賞には至らず入選止まり**(要確認)。そして後述の通り、**タイミング判定・スマホ対応・先行入力・練習モードといった本企画の中核要素は実装されていない**。差別化の余地は明確に存在する。
3. **ゲーム性のある作品は毎年入賞している**(2021優秀賞、2024優秀賞、2025優秀賞、2026最優秀賞)。ジャンルとしてのゲームは審査で不利ではなく、むしろ強い。
4. **2026年度は2026年8月28日に受賞発表済みで終了。** 応募先は次回(2027年度想定)になる。開催告知は未発表(要確認)。
5. 応募総数は **2023年39 → 2024年63 → 2025年96 → 2026年168作品** と急増しており、競争は年々激化している。

## 2. 最重要:先行作品『Typing Lyrics』(2023年入選)

- 作者:Rozelin(GitHub `Rozelin-dc`)
- リポジトリ:https://github.com/Rozelin-dc/magicalmirai2023-procon
- 公開デモ:https://rozelin-dc.github.io/magicalmirai2023-procon/
- 受賞:2023年 **入選**(最優秀賞・優秀賞ではない。要確認)

### 実装されている内容

| 項目 | 内容 |
|---|---|
| コアループ | 歌詞をタイピングし、**歌唱中にフレーズを完成させる**ことが目標 |
| 世界観 | タイピングでキャラにパワーを送り、楽曲のテンポに合わせてミク(曲により KAITO)が走る |
| ミス時 | キャラが転倒する |
| ローマ字入力 | **ヘボン式 / 訓令式を設定画面で事前に選択**。localStorage に保存 |
| スコア | 楽曲ごとの閾値を超えるとエンディング演出が変化。ハイスコアを localStorage 保存し「過去の自分と競う」 |
| 対応楽曲 | 6曲(king妃jack躍、生きること、唱明者、ネオンライトの海を往く、ミュウテイション、Entrust via 39) |
| 演出 | サビで光のスピード演出、コントラスト比配慮、全画面、SNS共有 |
| 技術 | React(TypeScript)、TextAlive App API、Sass、Vite、Vitest、React Icons、React Hot Toast |
| 対応環境 | **PC前提**。Windows推奨、Mac未確認、iPad+外部キーボードは確認済み。**スマホ非対応** |

### 本企画との差分(=差別化の根拠)

| 論点 | Typing Lyrics | 本企画 |
|---|---|---|
| **タイミング判定** | 文字単位の JUST/GREAT 判定は無い。「フレーズを歌唱中に打ち切れたか」+ 総合スコア閾値 | **かな確定時刻と発声時刻を突き合わせた文字単位の多段判定**がコア(§2.2) |
| **ローマ字表記ゆれ** | ヘボン式/訓令式を**プレイヤーが事前選択**=打ち方を1つに強制 | **トライ木で全表記を同時受理**(`shi/si`、`nn/n`、拗音分解も)。打ち方を強制しない |
| **打鍵が追いつかない問題** | 対策なし(全文字打鍵、閾値で難易度調整のみ) | **難易度別の密度制御(間引き)+ 先行入力バッファ**(§2.4, §2.5) |
| **練習手段** | なし | **リハーサルモード**(打鍵駆動で時間制約を外す、§2.5) |
| **スマホ** | 非対応 | **自前フリックパッドによる「1かな=1操作」モード**(§3.4) |
| **アート** | 通常のイラスト/エフェクト系 | **ドット絵 + 2010年前後の空気感**(過去作にドット絵作品は見当たらず) |
| **AI活用** | なし | 事前の譜面生成補助 + プレイ後の講評生成(§5) |

**評価**:コンセプトの重なりは大きいが、「音楽ゲームとしての判定設計」が本企画の中心にあるのに対し、先行作は「タイピング練習+演出」に寄っている。ここを明確に打ち出せば別作品として成立する。逆に言えば、**タイミング判定・スマホ・練習モードのどれも作り込めなかった場合、単なる後追いになる**。

## 4. 審査基準(要確認だが複数年で共通)

1. **クリエイティビティ** — 演出が楽曲と同期して魅力的に見えるか
2. **イノベーション** — アイデアがユニークで未来の創作文化を予感させるか
3. **完成度** — 一般的なブラウザ(PC・タブレット・**スマートフォン**など応募者の意図した環境)で正常動作するか、実装が技術的に優れているか

審査プロセス:クリプトン伊藤氏・産総研 加藤淳氏・後藤真孝氏らが**全応募作を実際に試用**して予備審査 → 入選10作発表 → 公式アプリ「ミクナビ」での一般投票 → 最終審査で最優秀賞1・優秀賞3を決定。

**示唆**:
- 「完成度」に**マルチデバイス動作が明記**されている。スマホ対応は評価軸に直結する。
- **一般投票が入る**ため、「短時間で楽しさが伝わるか」「スマホでも遊べるか」が票に効く可能性が高い。会場でスマホから触れることの価値は大きい。
- 「イノベーション」で、既に前例のあるタイピングゲームというジャンルは不利になりうる。**判定設計と入力方式の新規性を前面に出す必要がある。**

## 5. コンテスト外の類似サービス(一般市場)

| 名称 | 内容 | 本企画との関係 |
|---|---|---|
| **TypeSinger**(研究、2015、橋田光代ら / エンタテインメントコンピューティング2015) | 「歌うように弾く」歌詞タイピングゲーム。**歌唱の発音と同じタイミングで各文字を入力**させ、カラオケのようにリズミカルな打鍵技能を養う。従来の歌詞タイピングが正確性と速度しか見ておらず音楽的要素を欠く点を問題視 | **本企画のコア(かな確定時刻での判定)とほぼ同じ問題意識の先行研究**。論文を入手して判定設計の裏付け・引用に使う価値が高い |
| **BeatTyping**(Steam) | タイピング×音ゲー。「Beat Typing」「UTA Typing」の2モード。**複数のローマ字表記を受理**(じゃ = zya/ja/zixya/zilya、んだ = nda/nnda) | 表記ゆれ受理の実装方針の裏付け。商用作品として成立している証拠 |
| **歌謡タイピング劇場**(ハンゲ) | 音楽を聴きながら制限時間内に歌詞を入力。かな入力/ローマ字入力を選択可。観客のテンションを維持 | 長寿の定番。「歌詞を打つ」体験自体は目新しくない |
| **TypingTube / KeyTube / 歌打。** | **YouTube動画と連動**した歌詞タイピング。18万曲規模 | **当初検討していた「YouTubeにオーバーレイ」案は既に一般サービスとして成立済み**。不採用判断は妥当だった |
| **Typercussion** | ボカロ曲のリズムタイピング。200曲以上。ただし**打つのはランダムな48キー**で歌詞そのものではない | 「歌詞を打つ」点で本企画と差別化できる |
| **NicoFlick** | **フリック入力リズムゲーム**。プレイ中に歌詞を表示 | スマホのフリック×リズムゲームは前例あり。目新しさは主張しにくいが、実現可能性の裏付けにはなる |

**示唆**:歌詞タイピングというジャンル自体は一般市場で成熟している。本企画の勝ち筋は「TextAlive の文字単位タイミングデータを使った、楽曲同期の判定精度」と「マジカルミライ課題曲の世界観演出」に置くべきで、「歌詞を打てること」自体を売りにはできない。

## 6. 企画への反映事項

### 維持すべき判断
- TextAlive App API 採用(§1.1)
- かな確定単位のタイミング判定(§2.2)— **これが先行作との最大の差**
- ローマ字表記の全受理(§2.3)— 先行作の「方式を事前選択」より明確に優れる
- 先行入力・リハーサルモード(§2.5)
- スマホ対応(§3.4)— **審査基準の「完成度」と一般投票の両方に効くため、優先度を上げる価値がある**

### 見直しが必要な点
1. **「2010年代前後のボカロ黎明期」という世界観は課題曲とミスマッチの恐れがある。**
   コンテストの課題曲は毎年の楽曲コンテスト受賞曲(=新曲)であり、黎明期の曲ではない。「クリエイティビティ = 演出が楽曲と同期して魅力的に見えるか」が審査基準である以上、**曲の世界観を無視した固定テーマは減点要因になりうる**。
   → 対応案:ドット絵という表現手法は維持しつつ、**配色・エフェクトを楽曲の V/A(感情価・覚醒度)やサビ検出に応じて動的に変える**設計にする。「黎明期の再現」ではなく「ドット絵という手法で今の曲を表現する」に軸足を移す。
2. **ジャンルの既視感への対策を企画書の前面に置く。**
   応募時の作品説明で「タイピングゲーム」とだけ書くと前例の後追いに見える。「**楽曲同期の判定を持つリズムゲームであり、入力方式がタイピング**」という位置づけを明示する。
3. **スマホ対応をフェーズ2ではなく応募版スコープに入れることを検討。**
   一般投票と「完成度」評価の両面で効き、かつ TouchLyricWorld(優秀賞)の前例もある。ただし工数は増える。

### 新規に検討する事項
- TypeSinger の論文(情報処理学会 EC2015)を入手し、判定設計の妥当性確認と、作品説明での学術的裏付けに使う
- 次回開催(2027年度想定)の告知を待つ。告知は例年春頃と推測されるため、**それまでに検証スパイクとコア実装を進めておく時間的余裕がある**
