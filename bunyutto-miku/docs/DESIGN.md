# ぶにゅっとミク — 設計メモ

「片手で音の高さ、片手で顔をつまんで口の形」という操作を、
マジカルミライ 2025 課題曲 × 音ゲーに載せた企画。

## 操作

| 手 | 場所 | 役割 |
|---|---|---|
| 片手 | 盤面(6段のスティック)をタップ/なぞる | 音の高さ。なぞるとポルタメント |
| 片手 | ミクの顔を2本指でピンチ | 口の形(母音) = 音色 = 表情 |

**声が出るのは、盤面をタップしていて、かつ顔をピンチしているあいだだけ**(どちらか一方では鳴らない。
どちらを先に触ってもよく、そろった瞬間が発声=判定の瞬間)。

口の開閉だけでなく、**ピンチの向き×開閉で5母音**にして音のバリエーションを増やした。

| 母音 | ピンチ | 顔 | 音 |
|---|---|---|---|
| あ | 2本指でさわる(動かさない) | にこにこ(喜ぶ目)、小さく開口 | F=800/1250/2600 |
| い | 横にひろげる | ほっぺむにー(つままれた跡)、喜ぶ目、大きな笑顔 | 290/2250/3100 |
| う | 横からおさえる | ほっぺが押された跡、くの字の苦しげな目、ちゅっと突き出した口 | 320/1050/2350 |
| え | たてにつぶす | むぎゅっ、平たい顔、くの字の苦しげな目、横に開く口 | 520/1900/2650 |
| お | たてにひろげる | Oの口、くの字の目 | 500/900/2450 |

指を動かした**量**(amount)で顔の変形と音色が連続的に混ざる(顔の重みとフォルマントの重みは同じ値)。
オン・オフにならないよう、**形そのものを連続変形**させている: 目は「ひらき・反り・＞＜への変形量」、口は
「大きさ・上辺の平らさ・角の立ち・くちびるの太さ・舌」のパラメータを重みで補間する(型の切り替えは無い)。
ピンチの有効レンジは広め(開く側は基準の1.9倍で満量、つぼめる側は0.42倍)にして、指の動きの全域で連続して変わる。
`face-lab.html` のコマ送り表で、0〜100%の途中の形を確認できる。

## ノーツ = 歌詞の1音

- **タイミング**: 歌詞のモーラ(1音)の発声時刻。拍に乗るもの・語頭・フレーズ頭を優先して間引く
- **母音**: 歌詞の読みの母音。「歌詞どおりの口」をするのが操作そのもの(ミクが歌詞を口パクする形になる)
- **音の高さ**: コード進行から調を推定し(`key.js`)、ペンタトニック6段(ド レ ミ ソ ラ ド↑)に割り当てる。
  和音の構成音を優先し、フレーズごとに山なりになる。曲の和音と合うので、外してもだいたい気持ちよく鳴る
- **長音**: 発声が長いモーラは押したまま(「ー」を含む)。顔と段を保った時間で加点

難易度は「母音が変わるときの最小間隔」で決める(ピンチを作り直す時間が要るため)。

| | 母音変化 | 同じ母音 | 目安 |
|---|---|---|---|
| EASY | 760ms | 480ms | 0.5〜0.8音/秒 |
| NORMAL | 480ms | 300ms | 0.9〜1.2音/秒 |
| HARD | 320ms | 200ms | 1.3〜1.9音/秒 |

## 自由演奏

スタート画面の「ノーツなしで自由に鳴らす」で、ノーツも採点も無しに、曲に合わせて鳴らせる。
音階は曲の調なので、どこを鳴らしても曲に合う。曲の終わりまで行くと歌い出しの手前から繰り返す(Ⅱでもどる)。
通常のプレイでも、ノーツと関係なく鳴らした音は減点されない(窓の外のタップは自由演奏)。

## 判定(`judge.js`)

- タイミング ±70 PERFECT / ±130 GREAT / ±200 GOOD。取りこぼしは +230ms で確定(失敗音の遅れを抑える)
- **段が違う**: 取りこぼしにはならず、締め切りまでに合わせれば取れる(なぞって滑り込んでもよい)
- **顔が違う**: 当たるが GOOD 止まりで点が半分。打鍵の前160ms〜後150msに顔がそろえばよい
- 窓外のタップは自由演奏(減点なし)。楽器として鳴らす遊びを妨げない

## 音(`voice.js`)

ミクの歌声っぽい「あ・い・う・え・お」。モノフォニック。
声帯(倍音が 1/n^1.15 で減る丸い波×2本をわずかにずらす)+息 → フォルマント5本(F1〜F3 は母音ごと、F4・F5 は固定で母音ごとに明るさを変える) → 歌手フォルマント(3kHz)。
小柄な女声に寄せるためフォルマントを1.1倍、声域はミクの C4〜B5(トニックを C4〜B4 に置く)。
歌い出しに少し下からの「しゃくり」と息、ビブラートは少し遅れて乗る。立ち上がり 8ms。
響き: 合成した残響(ホール、1.8秒)をリミッター後の音にかける(声を止めたあとも余韻が残る。0.2秒後で持続音の3〜5割、0.5秒後で約1割)。声帯は3本をわずかにずらして重ね、厚みを出している。
本物の歌声ライブラリは使えないので、あくまで母音の合成による近似。
グラフは最初の操作で1本だけ作り、以降は AudioParam を動かすだけ(打鍵ごとにノードを作らない)。
母音の音量は 392Hz/659Hz で RMS を測ってそろえてある(`OfflineAudioContext` でスペクトルを確認できる)。

## 顔(`face.js`)

320×320 ドット(論理座標は80×80の4倍)・固定パレット・アンチエイリアス無し。表示は滑らかに縮小して、ドットが一見わからない細かさにしている。**可愛さが絶対条件**で、丸い「ちびミク」にしてある(目は小さめ)。
**変形するのは顔(表情と輪郭)だけ**で、髪・ツインテール・ヘッドホン・体はピンチで動かない。
目は**喜ぶ目(＾＾)とくの字の苦しげな目(＞＜)の2種類だけ**。舌は口の内側にだけ描く。頬は手を描かず、**つままれた/押された跡**で伝える。
**デザインはデータ**: 色・形・5表情・髪・動きはすべて `app/data/design/miku-face.json` にあり、`face.js` はそれを読んで描くだけ。
デザイン案を直すと本編に反映される(手順・項目の意味は `design/README.md`、確認は `face-lab.html`)。`?design=URL` で別案を試せる。
鋭いまつ毛・歯・ぎざぎざの前髪・濃い輪郭線・怒り眉は使わない(初版はこれで怖がられた)。
表情は `EXPR` テーブルの1行。目・口の型は `drawEye` / `drawMouth`。

## データ

- `app/data/songs/*.json` … 課題曲6曲の拍・コード・歌詞時刻+読み(`tools/build-songs.mjs` で生成)。
  実行時は TextAlive の Player から同じ形を作り、読みだけここから補う。デモモードと単体テストはこれだけで動く
- 音源は含めない(TextAlive 経由でのみ再生)

## 検証した範囲

- 単体テスト 28 件(`node --test bunyutto-miku/test/*.test.mjs`): 読み→母音、コード解析、調推定、譜面の間隔/決定性、判定、ピンチ
- 実機相当: CDP のマルチタッチでピンチ+タップ+なぞり、譜面どおり弾くボット
  (正しく弾く→全 PERFECT / 顔違い→点半分 / 放置→全 MISS / プレイ中のノード生成なし)
- 実楽曲: ヘッドレスで TextAlive に接続し、カード URL フォールバック → 同一譜面の生成 → 再生とシークまで確認
- **未検証**: 実機スマホでの操作感(2本指ピンチと片手タップの同時操作の快適さ、出力遅延)。
  設定の「タイミング補正」で調整できる。画面下のバッジに `snd:` と `lat:` を出している
