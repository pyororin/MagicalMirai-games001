# 設計書 v2: ミクの本体はツインテールである（リズムアクション版）

> v1（自由描画で髪を生やす）から**ゲーム性を根本再設計**。
> 「描く」を捨て、「リズムに合わせて打つ」に変えた。v1 は git 履歴に残る。

## 0. 一行で

**日常の物に、リズムで、ツインテールを打ち込む。**
4 拍目でタップ、小節線をまたいでリリース。左右そろえば「ミク！」。
それを積み上げて、曲の終わりに“日用品ミクの大集合”を作る。

---

## 1. なぜ作り直したか（v1 の敗因分析）

| v1 の要素 | 何が起きたか | v2 での扱い |
| --- | --- | --- |
| 自由なドラッグで髪を描く | 入力の自由度が高すぎて、**手触りが毎回違う＝上達感がない** | 廃止。入力を「タップ／スライド／リリース」の 3 動作に固定 |
| 髪の物理揺れ | 見た目は良いが**遊びに関与しない**（触っても何も起きない） | 廃止。演出コストをリズム反応に振り替える |
| ビート適合率でスコア | 描いている最中の平均値なので**成否が瞬間で分からない** | 1 打ごとに即判定・即音・即表示 |
| サビで自動採点 | 数十秒に 1 回しか報酬が来ない | **1 小節ごと**に報酬が来る |

**根本問題**: v1 は「お絵かきツールにリズム判定を後付け」した構造だった。
音楽ゲームは**音が先で、操作がそれに答える**構造でなければ気持ちよくならない。

## 2. 設計の背骨（リズム天国から借りる 3 原則）

つんく♂のリズム天国は「ノーツを見て押す」音ゲーへの違和感から生まれ、
**慣れれば目をつぶってもパーフェクトが狙える**ことを設計目標に置いている
（ゲーム中はわざと視覚妨害を入れて目押しを封じる）。ここから 3 つ借りる。

### 原則 A: 合図は耳から来る（目押しさせない）
どちらの房を打つかは**ステレオの定位**で伝える。左耳で鳴ったら左、右耳なら右。
画面にも印は出すが、**印は音より遅れて出す**ので目押しは成立しない。
→ 実装は `StereoPannerNode` 1 個（枯れた技術）。

### 原則 B: 操作そのものが演奏になっている
「押すべきタイミングで押す」＝アクションとリズムにズレがない構造にする。

```
  1     2     3     4  |  1
  ○     ○     ○   ★TAP | ★RELEASE
              合図  ↑タメ(シャラララー)  ↑着地(シャキーン)
```

4 拍目にタップし、**小節線をまたいで次の 1 拍目でリリース**する。
これは音楽でいう**アウフタクト（弱起）から小節頭への解決**そのもので、
「タメて、頭で決める」という体の動きが、そのまま音楽の解決と一致する。
気持ちよさに音楽理論上の裏付けがある。

### 原則 C: 失敗は罰でなく笑い
ミスしても止まらない。髪が生えない／変な向きに生える／ハゲのまま背景に並ぶ。
**最終ギャラリーに失敗作も残る**ので、事故がそのままネタになる。

## 3. 基本ループ — 1 房 = 1 小節、房は 2 種類

四拍子の中で完結する。**判定するのはタップ 1 点だけ**。
ただし**飛んでくるものが 2 種類**あり、何が来るかで叩く拍が変わる。

```
□ 髪留めが飛んできたら          〜 髪が飛んできたら
1        2        3        4     1        2        3        4
                  ▲タップ └伸ばす┘▲確定                     ▲タップだけで確定
```

| 飛んでくるもの | 叩く拍 | すること | できる髪 |
| --- | --- | --- | --- |
| **□ 髪留め** | 小節の最後の 1 拍前 | タップして、**最後の拍まで指でなぞる** | **なぞった線がそのまま髪の形** |
| **〜 髪** | 小節の最後の拍 | **タップするだけ** | お題の髪型どおりの綺麗な髪 |

出現比はおよそ 6:4。房ごとにハッシュで決まるので、譜面データは持たない。

### なぞった線が、そのまま髪になる

指の軌跡を 3 点移動平均で 1 度だけならし（手ぶれを落とす）、弧長で等間隔に 19 点へ間引いて、
**その折れ線をお題ローカル座標で保存する**。描画も採点もこの折れ線を見るので、
**画面の髪は自分が描いた線そのもの**になる。背景へ縮小しても形は保たれる。

タップだけで付く房は、お題の髪型から理想の曲線を合成して同じ形式で持つ。
どちらの房も同じ描き方・同じ採点にかけられる。

### 叩く拍は耳で分かる

その小節で**自分が叩く拍の音だけ**が左右にパンする。もう一方は中央で鳴る。

| 拍 | 音 | 髪留めの房 | 髪の房 |
| --- | --- | --- | --- |
| 最後の 1 拍前 | 硬い「カンッ」 | **左右にパン** | 中央 |
| 最後の拍 | 柔らかい「ポワーン」 | 中央 | **左右にパン** |

「どちら側か」も「どの拍か」も耳だけで取れる（原則 A の実装）。

1 房 = 1 小節、2 房で 1 体。つまり **1 体 = 2 小節**（130BPM で約 3.7 秒）。
2 本目が生えた最後の拍で「ミク！」が出て、次の小節から次の体が始まる。
曲と拍の音量は**プレイヤーが 2 本のつまみで調整できる**（既定は 50 / 50）。
**実曲の楽曲だけは WebAudio を通らない**（TextAlive の mediaElement が直接鳴らす）ので、
楽曲のつまみは `songGain` と `player.volume` の両方へ渡す。値は localStorage に残る。

### 拍子に依存しない定義

課題曲には**四拍子でない曲がある**（2025 年課題曲「ロンリーラン」は 6 拍子）。
そこで実装上は拍子を数えず、**小節の中の相対位置**で定義してある。

> **髪が生えるのは小節の最後の拍。髪留めを置くのはその 1 拍前。**

四拍子ならこれは「4 拍目で髪・3 拍目で髪留め」と一致する。
6 拍子なら 6 拍目と 5 拍目になり、**どの曲でもスライド区間はきっかり 1 拍**に保たれる。

### 一時停止

曲の途中でいつでも止められる。止めている間は曲の時計も進めず、予約済みの音も
出力ごと絞るので、鳴り残しが出ない。停止中は**再開**と**メニューへ戻る**を選べる。
伸ばしかけの房は、そこまで描けていれば確定し、まだ短ければお題どおりの髪を付けて終える
（一時停止した人を罰しない）。

### 髪留めが滑らかに近づいてくる

タップの 3 拍前から、髪留めと房の影が画面外側に現れ、**連続的に**近づく。
到達した瞬間がタップの拍。

### お題は動かない

お題オブジェクトは**定位置に現れて、そのまま動かない**。
最初の房を掴む 4 拍前からその場でフェードインするので出現位置は早く分かるし、
**伸ばしている最中に的が動かない**ので狙った角度がずれない。
判定が終わった体は、その場から背景の空き位置へ**飛んでいく**（＝退場と配置が同じ動作）。
次の体は前の体が飛び立った直後に同じ場所へ現れるので、重ならない。

### 髪型がお題として提示される

体ごとに**髪型**（ストレート／ハの字／ロング／外ハネ／ショート／ふんわりロング）が
抽選され、画面には**黄色い破線の下書き**として「この向きに、この長さで伸ばせ」が示される。
髪型は**角度と長さの目標値の組**であり、ミク度の角度点・長さ点はこの目標との差で決まる。

- タイミングは耳（拍と定位）、**形は目で**——役割が分かれるので目押しにはならない
- 同じお題でも髪型が変われば別の課題になる。**組み合わせで飽きが来ない**

### 触った位置から髪が生える

タップ位置は厳密でなくてよい。**触ったところが髪の根元**になる。
ただし**左右のクランプはしない**。左の房を右側に置くこともでき、そのときは
ツインテールとして成立しないので**ミク度が大きく下がる**（§4 の X）。
「どちら側か」は音の定位で示されているので、聞いていれば間違えない。

### 難易度は「打っていれば成立する」ところに置く

| 判定 | 窓（拍） | 結果 |
| --- | --- | --- |
| PERFECT | ±0.16 | 髪。満点 |
| GOOD | ±0.36 | 髪 |
| **OK** | ±0.72 | **髪は生える**（低得点、コンボは切れない） |
| MISS | それ以外／無操作 | ネギ |

**OK 帯まで髪が生える**のが要点で、ネギになるのはタップを大きく外したか、
そもそも打っていないか、置いたまま一切伸ばさなかったときだけ。

### 失敗すると、ネギが生える

その房には**ネギが斜め上へ真っ直ぐ生える**。
垂れ下がる髪との対比で、失敗が一目で分かる（ツインテールは落ち、ネギは跳ねる）。
同時に**ブービー音**（クイズの不正解のような「ブッブー」）が鳴り、耳でも失敗と分かる。
ネギのままのミクも背景に並び、最後のギャラリーで一番笑いを取る。

## 4. ミク度 — 厳密な定義

本作の根幹。完成した 1 体につき **0〜100** の整数で決まる。
**リズム 36 点・造形 64 点**。造形は「お題の髪型どおりか（角度）」と
「そもそもツインテールの形になっているか」を柱にする。

**難易度を変えてもこの定義は動かない**（§5.6）。変わるのは判定窓とガイドの出し方だけなので、
難易度をまたいでもミク度は同じ物差しのままになる。

> 一覧表は [README の「ミク度 — 判定条件（仕様）」](../README.md#ミク度--判定条件仕様) にもある。

### 前提となる量

体には房 L・R の 2 本がある。房 *i* は**折れ線 pts**（付け根からの相対座標）を持ち、
そこから次の量を測る（`hair.js` の `pathMetrics`）。

| 記号 | 意味 |
| --- | --- |
| *g<sub>i</sub>* | タップ判定 ∈ { PERFECT, GOOD, OK, MISS } |
| *θ<sub>i</sub>* | 付け根→毛先の向き。画面座標なので **+y が下** |
| *ℓ<sub>i</sub>* | 弧長（折れ線の長さ。直線距離ではない） |
| *reach<sub>i</sub>* | 毛先までの直線距離 ÷ 弧長。1 に近いほど素直に伸びている |
| *descent<sub>i</sub>* | 付け根側 15% を除いた区間のうち、下へ向かっている割合 |
| *(x<sub>i</sub>, y<sub>i</sub>)* | 髪留めの位置（お題の中心を原点とするローカル座標） |
| *style* | その体に出された髪型。目標角 `ang` と目標長比 `len` を持つ |
| *size* | お題の大きさ `max(h, w × 0.62)` |

目標角は **右房 = `style.ang`、左房 = `π − style.ang`**、目標長は **`style.len × size`**。
MISS の房は髪ではなく**ネギ**になり、その房の R・A・T・P はすべて 0 になる。

### 加点（合計 100）

**① 拍の正確さ R（0〜36）** — 房ごと 18 点

```
r(PERFECT)=18,  r(GOOD)=11,  r(OK)=4,  r(MISS)=0
R = r(g_L) + r(g_R)
```

**② 角度 A（0〜18）** — 房ごと 9 点。**お題の髪型どおりか**

```
err_i = |normalize(θ_i − target(side_i, style))|
A_i   = 9 × clamp01(1 − err_i / 0.35)        0.35 rad(≒20°)ずれると 0 点
```

**③ ツインテールらしさ T（0〜16）** — 房ごと 8 点。**房の形そのもの**を見る

```
素直さ 4 × clamp01((reach_i − 0.55) / 0.20)
       … 巻き込み・折り返し・往復はここで落ちる
垂れ   4 × clamp01((descent_i − 0.45) / 0.40)
       … 上へ跳ね上げた房はここで落ちる
```

まっすぐ落とした房も、ゆるく弧を描いた房も、理想曲線も満点になる。
**「髪に見えない形」だけを落とす**設計にしてある（うねりは髪らしさとして許容する）。

**④ つけ位置 P（0〜12）** — 房ごと 6 点

```
外向き度 o_i = (x_i × dir_i) / (w/2)        dir = 左房 −1 / 右房 +1
P_side_i   = 4 × clamp01((o_i + 0.02) / 0.30)
P_height_i = 2 × clamp01(1 − |h_i − 0.88| / 0.7)   h_i = −y_i / (h/2)
```

**⑤ 左右の対称 S（0〜10）** — 両房とも髪で、かつ**左右を取り違えていない**ときのみ

```
Δθ = |normalize((π − θ_L) − θ_R)|
S = 5 × clamp01(1 − Δθ / 0.55) + 5 × clamp01(1 − |ℓ_L − ℓ_R| / max(ℓ_L, ℓ_R) / 0.45)
```

**⑥ 長さ L（0〜8）** — 両房とも髪のときのみ

```
L = 8 × clamp01(1 − |((ℓ_L + ℓ_R)/2) / (style.len × size) − 1| / 0.55)
```

### 減点

**X 左右取り違え（房ごと −12）**

```
房 i が「その側と反対の x」に置かれていたら wrongSide
X = 12 × (wrongSide の房数)
1 本でも wrongSide があれば S = 0
```

### 合計と称号

```
ミク度 M = clamp(R + A + T + P + S + L − X, 0, 100)
```

| M | 掛け声 | 称号 | 背景での光り方 |
| --- | --- | --- | --- |
| 93〜100 | 「ミクーッ！」 | 本人 | **強く光る** |
| 80〜92 | 「ミク！」 | ほぼミク | **淡く光る** |
| 64〜79 | 「ミク。」 | ミク見習い | かすかに光る |
| 42〜63 | 「ミク？」 | 言い張ればミク | — |
| 0〜41 | 「だれ？」 | ただの◯◯ | — |

自動検証での実測:

| プレイ | ミク度 | 称号 |
| --- | --- | --- |
| お題どおり（6 髪型すべて） | 100 | 本人 |
| 角度が 20° ずれ | 82 | ほぼミク |
| 左右を 1 本取り違え | 70 | ミク見習い |
| 左右を 2 本とも取り違え | 54 | 言い張ればミク |
| ぐるっと巻いた（reach 0.06） | 54 | 言い張ればミク |
| 上へ跳ね上げた（descent 0） | 61 | ミク？ |
| 全房が OK 判定（拍が甘い） | 68 | ミク見習い |
| 片方ネギ | 39 | ただの◯◯ |
| 無操作 | 0 | ただの◯◯ |

**片方でもネギになるとミク度は最大 45**、**左右を取り違えると最大 52**。
「ツインテールは 2 本そろって、正しい側に、正しい向きと形で初めて意味を持つ」——
主題がそのまま採点式になっている。

### 記録と可視化

- 体ごとに **M と内訳（R/A/T/P/S/L/X）と房ごとの判定**を保持し、スコアに `M × 5` を加算する
- **64 点以上の体は背景で淡く光り続ける**（80 点以上、93 点以上と段階的に強くなる）
- **その時点の最高記録の体にだけ★付きで称号を表示**する
- 曲の終わりのリザルトで**ベスト 5 を内訳つきで一覧**する

### 難易度設計の意図

タイミングの**合否**（ネギになるか）は難易度で動かすが、**ミク度の式は動かさない**。結果として:

- やさしいでも最後まで遊べる（ネギだらけにならない）
- しかし「ミク！」以上は、拍・角度・形・左右をすべて揃える必要がある
- 難易度をまたいでスコアが比較できる

## 4.5 ステージとお題オブジェクト

背景は**ステージ**で、そのステージにちなんだお題だけが出る。
体 4 つごとに次のステージへ移り、背景が入れ替わる（作ったミクは残る）。

| ステージ | 背景 | お題（6 種） |
| --- | --- | --- |
| 台所 | タイル壁・木の天板・吊り照明 | ネギ／炊飯器／マグカップ／しょうゆさし／フライパン／電気ケトル |
| 通学路 | 夕暮れのビル影・路面のセンターライン | 郵便ポスト／信号機／カラーコーン／自動販売機／消火栓／ポリバケツ |
| 机の上 | コルクボードの方眼・木目・デスクライトの光 | ペットボトル／目覚まし時計／スティックのり／ホチキス／えんぴつ立て／電卓 |
| ライブハウス | 振り回されるムービングライト・客席のシルエット | ギターアンプ／スピーカー／マイクスタンド／ミラーボール／ペンライト／モニタースピーカー |

- **計 24 種**。シルエットが特徴的で、**髪をつけた瞬間に化ける**ことが選定基準
- お題はステージ内で**互いに素な歩幅で巡回**させ、続けて同じ物が出ないようにしてある
- ライブハウスだけは「ミクが本当にいる場所」なので、最後のギャラリーが意味を持つ

## 5. 曲構造との連動（TextAlive の使いどころ）

| API | 用途 | 実装状況 |
| --- | --- | --- |
| `data.getBeats()` | 拍と小節位置。**譜面そのもの**（小節へ束ね、最後の拍＝髪／2 拍前＝髪留め） | 実装済み |
| `video.findChar()` | スライド中に流す歌詞の星。**伸ばした髪に歌詞が入る** | 実装済み |
| `video.duration` | 曲の終わり＝リザルト発火 | 実装済み |
| `getVocalAmplitude()` / `getMaxVocalAmplitude()` | 背景のミクたちの揺れ、**盛り上がり区間の検出**（§5.5） | 実装済み |
| `findChorus()` | サビ。髪型をロング寄りにし、決めポーズを出す（§5.5） | 実装済み |
| `findChord()` | 拍の音・シャラララ・シャキーンの音程を和音に合わせる | 実装済み |
| `getValenceArousal()` | ステージ抽選（明るい曲＝賑やかな場所） | 次段階 |

### 効果音を和音に乗せる（`findChord`）

鳴らす音の音程を、その瞬間のコードの三和音から取る。

| 音 | 使う音 |
| --- | --- |
| 髪留めの拍「カンッ」 | 根音（2 オクターブ上）＋ 五度 ＋ オクターブ |
| 髪が生える拍「ポワーン」 | 三和音 ＋ 根音の 1 オクターブ下 |
| 伸ばしている間「シャラララー」 | 三和音を積み上げて 11 音駆け上がる |
| 髪が生える「シャキーン」 | 落ち着く先を五度に置く |
| 決めポーズ「キメ！」 | 分散和音 |

コード名は `"Am"` だけでなく `"EM7/F"` `"Esus2/C#"` `"G#7/C"` `"Bbm7"` のように返るので、
`/` の前だけを見て根音と三度・五度に落とす（詳細は `ontology/textalive.yaml` の `chord-name-parsing`）。
**外れた音が鳴らない**ので、合いの手が曲の一部に聞こえる。

課題曲（マジカルミライ 2025 楽曲コンテスト受賞 6 曲）での実測:

| 曲 | 拍子 | 小節 | ミク（体） | 1 拍 | スライド区間 |
| --- | --- | --- | --- | --- | --- |
| ロンリーラン / 海風太陽 | **6** | 135 | 67 | 0.300s | 0.60s |
| ストリートライト / 加賀(ネギシャワーP) | 4 | 94 | 47 | 0.513s | 1.03s |
| アリフレーション / 雨良 Amala | 4 | 125 | 62 | 0.461s | 0.92s |
| インフォーマルダイブ / 99piano | 4 | 139 | 69 | 0.309s | 0.62s |
| ハロー、フェルミ。/ ど～ぱみん | 4 | 165 | 82 | 0.333s | 0.67s |

**曲がそのまま譜面になる**ので、曲ごとに難度も尺も自動的に変わる。
1 曲で 47〜82 体たまるため、背景のミクは数が増えるほど全体を縮小して画面に収める。

## 5.5 盛り上がり区間（サビ）

サビでは 3 つが変わる。

1. **髪型がロング寄りになる**（ロング／ふんわりロング／ストレート）。
   同じ 2 拍でより長く伸ばすことになるので、**操作の構造を変えずに手が忙しくなる**。
2. **決めポーズが増える**。体が完成した次の拍——つまり次の小節のアタマ——に
   画面中央へ輪が閉じ、そこで叩くと「キメ！」。ここは房のタップの 1 拍前で必ず空いており、
   スライド中でもないので指が競合しない。外しても罰はない（コンボとスコアのボーナスのみ）。
   1 体あたりの入力が 2 回から 3 回になる。
3. **画面が色づく**（ピンクの薄いグラデーションと「♪ サビ」表示）。

### サビの検出 — `findChorus` だけでは足りなかった

`getChoruses()` は課題曲で **1 区間しか返らない**ことが実測で分かった。

| 曲 | 尺 | `getChoruses()` |
| --- | --- | --- |
| ロンリーラン | 222 秒 | 1 区間（71〜107 秒）= 16% |
| ハロー、フェルミ。 | 202 秒 | 1 区間（2〜13 秒）= 5%（**イントロに乗る**） |

そこで**ボーカル音量の包絡**で補う。0.5 秒刻みでサンプルし、4 秒の移動平均でならし、
**その分布の上位 30%（分位点）**を盛り上がりとする。短い山（8 秒未満）は捨て、
短い谷（4 秒未満）は繋ぐ。`findChorus()` の結果とのORを取る。

> しきい値を**ピーク比**（「ピークの 62%」など）で決めてはいけない。
> ならした包絡は歌っている間ずっと平らなので、曲の 51〜86% が該当して
> 「常時サビ」になる。分位点で切ると自動的に曲ごとの分布に追従する。

課題曲 6 曲での実測（分位点方式）:

| 曲 | 盛り上がり区間 | 割合 |
| --- | --- | --- |
| ロンリーラン | 84–99 / 145–169 / 196–222 | 39% |
| ストリートライト | 62–85 / 113–132 / 163–177 | 33% |
| アリフレーション | 56–74 / 120–141 / 183–193 / 199–214 | 36% |
| インフォーマルダイブ | 45–61 / 91–103 / 135–158 | 38% |
| ハロー、フェルミ。 | 59–86 / 158–193 | 36% |
| パレードレコード | 54–70 / 94–112 / 146–157 / 162–192 | 44% |

どの曲でも 2〜4 山・3〜4 割に収まり、演出の土台として使える。

## 5.6 難易度

**ミク度の定義は難易度で変えない**（角度の許容 0.35rad は全難易度で共通）。
変わるのは「拍の判定窓」「髪型ガイドの出し方」「サビの決めポーズ」だけ。
こうしておくと、難易度をまたいでもミク度は同じ物差しのままになる。

| | 窓（ネギ） | PERFECT | GOOD | 髪型ガイド | 決めポーズ |
| --- | --- | --- | --- | --- | --- |
| やさしい | ±1.00 拍 | ±0.16 | ±0.36 | 常時 | なし |
| ふつう | ±0.72 拍 | ±0.11 | ±0.26 | 近づく間 | あり |
| むずかしい | ±0.45 拍 | ±0.07 | ±0.17 | **伸ばす間だけ** | あり |

「むずかしい」では髪型の下書きが伸ばし始めるまで出ないので、
**お題の名前を見て形を思い出す**必要がある。自動検証での実測（130BPM で 0.20 秒遅れのプレイ）:
やさしい／ふつうは全体が「ミク見習い」、むずかしいは大半がネギになった。

## 6. リリックアプリとしての核（コンテスト要件）

本作は音ゲーだが、**歌詞が主役でなければ応募要件を満たさない**。3 点で担保する。

1. **星＝歌詞**: スライド中に流れる「シャラララー」の星は、その瞬間に歌われている
   歌詞の一文字ずつ。髪は歌詞でできている（v1 から継承した主題）。
2. **掛け合い**: 「ミク！」の掛け声はフレーズの切れ目に置く。歌が問い、プレイヤーが答える。
3. **完成体が歌詞を纏う**: 背景に並んだミクの周りを、その体を作ったときの歌詞が回る。
   曲終わりのギャラリーは、**曲全体の歌詞が並んだ光景**になる。

---

## 7. リザルト（曲の終わり）

背景に**ランダムな位置・大きさ**で散らばった全ミクがカーテンコール。ボーカル音量に合わせて一斉に揺れる。

```
     [炊飯器ミク] [ネギミク] [ポストミク] [ハゲた消火器]  ← 今日の成果
              総スコア 18,420  /  最大コンボ 14
                   「ミクだらけ！」
```

- 失敗作（ハゲ）も並ぶ。**そこが一番笑える**。
- 1 枚絵としてスクリーンショットしたくなる構図にする（会場の一般投票対策）。

## 8. 追加提案（v2 で新規に足す遊び）

順に検討し、採否を決めた。

| # | 案 | 判定 | 理由 |
| --- | --- | --- | --- |
| 1 | **スライド方向で髪型が変わる**（下＝ストレート／外＝広がり） | **採用・変更あり** | 当初は「方向は自由・判定に使わない」としたが、それだと形を作る動機が消えて 1 房の作業が単調になった。**髪型をお題として提示し、角度と長さを採点する**形に変更（§4 の A・L）。タイミングは耳・形は目、と役割が分かれるので目押しにはならない |
| 1b | **左右を取り違えたら大きく減点** | **採用** | どちら側かは音の定位で示している。聞いていれば分かるので、間違いは「聞いていない」ことの結果になる（原則 A の強化） |
| 1c | **ステージ制**（背景 4 種と、そこにちなんだお題） | **採用** | 24 種のお題が「たまたま並んだ雑貨」ではなく**場所の情景**になる。曲の進行＝場所の移動として読める |
| 2 | **ステレオ定位で左右を指示** | **採用** | 原則 A の実装。ヘッドホンで化ける |
| 3 | **コンボで背景のミクが合いの手** | **採用** | 音楽的報酬。上手いほど曲が厚くなる＝リズム天国の「ノリ」 |
| 4 | **カウントイン（3・4）** | **採用** | 初見で入れる。教える設計 |
| 5 | **ハゲのまま背景に並ぶ** | **採用** | 失敗の笑い。リプレイ動機 |
| 6 | オブジェクトごとに固有リズム | 見送り | 覚える負荷が高く、リズム天国の「1 ゲーム 1 リズム」原則に反する |
| 7 | 長押しで髪を伸ばし続ける | 見送り | 拍から外れる自由入力は原則 B に反する |
| 8 | 対戦・オンラインランキング | 見送り | 応募規模を超える。将来案 |
| 9 | **観賞モード**（無操作時に自動演奏） | **採用** | コンテスト要件。手が勝手に打つ様子自体が見て面白い |

## 9. 技術方針（枯れた技術の水平思考）

| 技術 | 本来の用途 | 転用 |
| --- | --- | --- |
| `StereoPannerNode` | 音像定位 | **左右どちらを打つかの指示**（目押し封じ） |

| P6 | 実機（スマホ）での手触り調整、`getValenceArousal` によるステージ抽選、応募 | 次 |

### 構成（二重管理をしない）

```
app/src/game/     ゲーム本体（stages / score / hair / audio / core）
app/src/song/     ソングアダプタ（mock = 擬似曲 / textalive = 実曲）
app/index.html    実曲版（TextAlive 接続）
app/mock.html     擬似曲版（通信・トークン不要。?bars=8&bpm=100 で尺とテンポを変えられる）
```

`core.js` は楽曲を**アダプタ越しにしか触らない**。アダプタが満たす契約は
`ready / time / atAudio / beat(k) / bar(i) / barIndexAt / onBeat / charAt / vocalAt / ended` の 9 つだけで、
擬似曲と実曲はこの契約の別実装になっている。
モックで詰めた手触りが、そのまま実曲版の手触りになる。
