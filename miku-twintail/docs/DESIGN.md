# 設計書 v2: ミクの本体はツインテールである（リズムアクション版）

> v1（自由描画で髪を生やす）から**ゲーム性を根本再設計**。
> 「描く」を捨て、「リズムに合わせて打つ」に変えた。v1 は git 履歴に残る。

## 0. 一行で

**日常の物に、リズムで、ツインテールを打ち込む。**
4 拍目でタップ、小節線をまたいでリリース。左右そろえば「ミク！」。
それを積み上げて、曲の終わりに“日用品ミクの大集合”を作る。

---

## 1. なぜ作り直したか（v1 の敗因分析）

| v1 の要素 | 何が起きたか | v2 での扱い |
| --- | --- | --- |
| 自由なドラッグで髪を描く | 入力の自由度が高すぎて、**手触りが毎回違う＝上達感がない** | 廃止。入力を「タップ／スライド／リリース」の 3 動作に固定 |
| 髪の物理揺れ | 見た目は良いが**遊びに関与しない**（触っても何も起きない） | 廃止。演出コストをリズム反応に振り替える |
| ビート適合率でスコア | 描いている最中の平均値なので**成否が瞬間で分からない** | 1 打ごとに即判定・即音・即表示 |
| サビで自動採点 | 数十秒に 1 回しか報酬が来ない | **1 小節ごと**に報酬が来る |

**根本問題**: v1 は「お絵かきツールにリズム判定を後付け」した構造だった。
音楽ゲームは**音が先で、操作がそれに答える**構造でなければ気持ちよくならない。

---

## 2. 設計の背骨（リズム天国から借りる 3 原則）

つんく♂のリズム天国は「ノーツを見て押す」音ゲーへの違和感から生まれ、
**慣れれば目をつぶってもパーフェクトが狙える**ことを設計目標に置いている
（ゲーム中はわざと視覚妨害を入れて目押しを封じる）。ここから 3 つ借りる。

### 原則 A: 合図は耳から来る（目押しさせない）
どちらの房を打つかは**ステレオの定位**で伝える。左耳で鳴ったら左、右耳なら右。
画面にも印は出すが、**印は音より遅れて出す**ので目押しは成立しない。
→ 実装は `StereoPannerNode` 1 個（枯れた技術）。

### 原則 B: 操作そのものが演奏になっている
「押すべきタイミングで押す」＝アクションとリズムにズレがない構造にする。

```
  1     2     3     4  |  1
  ○     ○     ○   ★TAP | ★RELEASE
              合図  ↑タメ(シャラララー)  ↑着地(シャキーン)
```

4 拍目にタップし、**小節線をまたいで次の 1 拍目でリリース**する。
これは音楽でいう**アウフタクト（弱起）から小節頭への解決**そのもので、
「タメて、頭で決める」という体の動きが、そのまま音楽の解決と一致する。
気持ちよさに音楽理論上の裏付けがある。

### 原則 C: 失敗は罰でなく笑い
ミスしても止まらない。髪が生えない／変な向きに生える／ハゲのまま背景に並ぶ。
**最終ギャラリーに失敗作も残る**ので、事故がそのままネタになる。

## 3. 基本ループ（1 体 = 4 小節）

```
小節 1   [予告]  オブジェクトがせり上がる。カウントイン「3・4」
小節 2   [左]    3拍目に左から合図音 → 4拍目TAP → スライド → 次の1拍目RELEASE
小節 3   [右]    3拍目に右から合図音 → 4拍目TAP → スライド → 次の1拍目RELEASE
小節 4   [判定]  「ミク！」の掛け声＋スコア。完成体が背景へ歩いていく
```

130BPM なら 1 体あたり約 7.4 秒。3 分の曲でおよそ 24 体。
セクションによって密度を変える（§5）。

### 3 つの操作と 3 つの音

| 操作 | タイミング | 音 | 意味 |
| --- | --- | --- | --- |
| **タップ** | 4 拍目 | ポンッ（合図と同じ定位） | 髪の根元をつかむ |
| **スライド** | 4 拍目〜次の 1 拍目 | **シャラララー**（星が流れる） | 髪を伸ばす／タメ |
| **リリース** | 次の 1 拍目 | **シャキーン**（金属質の決め音） | 髪が確定する |

スライド中に流れる星は、**いまミクが歌っている歌詞の文字**（§6）。

---

## 4. 判定とスコア

### 判定窓（拍長を B とする）
| 判定 | 窓 | 表示 |
| --- | --- | --- |
| PERFECT | ±0.10 B | キラッ |
| GOOD | ±0.22 B | ○ |
| MISS | それ以外／4 拍目以外でタップ | ズコッ |

タップとリリースを**別々に判定**する。タップは良いがリリースが遅い＝
「髪が伸びすぎ」として見た目にも反映（長い髪になる）。**判定が見た目になる**。

### 掛け声（左右そろった瞬間）
音声はブラウザの読み上げ（Web Speech API）で発話する。

| 左右の結果 | 掛け声 | 称号例 |
| --- | --- | --- |
| PERFECT × 2 | **「ミク——！！」** | 本人 |
| PERFECT + GOOD | 「ミク！」 | ほぼミク |
| GOOD × 2 | 「ミク。」 | ミク見習い |
| 片方 MISS | 「ミク？」 | 片ツインテール |
| 両方 MISS | 「……だれ？」 | ただの炊飯器 |

> **法務メモ**: ミクの音声素材は使用しない。掛け声は**ブラウザ内蔵の合成音声**で、
> 機械音声であること自体がボーカロイド的なユーモアになる。
> 非対応環境ではフォルマント合成音＋大きな文字表示にフォールバックする。

### スコア
```
1 房   = タップ精度 + リリース精度            (最大 100)
1 体   = 左房 + 右房 + 左右対称ボーナス       (最大 250)
コンボ = 連続 PERFECT 数で倍率 1.0 → 2.0
```

## 5. 曲構造との連動（TextAlive の使いどころ）

セクションによってリズムパターンを変える。**曲が難易度をデザインする**。

| 区間 | パターン | 1 体あたり | 意図 |
| --- | --- | --- | --- |
| イントロ | 予告のみ（お手本デモ） | — | 教える |
| A メロ | 4 拍目のみ | 4 小節 | 基本形を体に入れる |
| B メロ | 2 拍目 & 4 拍目 | 2 小節 | 密度を上げる |
| **サビ** | 4 拍目 + 8 分裏（シャラシャラ連打） | 2 小節 | 最高潮 |
| 間奏 | 休符 | — | 休憩＋背景のミクたちが踊る |

| API | 用途 |
| --- | --- |
| `findBeat()` | 拍・小節位置の取得（判定の基準そのもの） |
| `findChorus()` | サビ判定 → パターン切替 |
| `video.findChar()` | スライド中に流す歌詞の星 |
| `findChord()` | 合図音・シャキーンの音程をコードに合わせる |
| `getVocalAmplitude()` | 背景のミクたちの揺れ |
| `getValenceArousal()` | オブジェクト抽選（明るい曲＝賑やかな物） |

## 6. リリックアプリとしての核（コンテスト要件）

本作は音ゲーだが、**歌詞が主役でなければ応募要件を満たさない**。3 点で担保する。

1. **星＝歌詞**: スライド中に流れる「シャラララー」の星は、その瞬間に歌われている
   歌詞の一文字ずつ。髪は歌詞でできている（v1 から継承した主題）。
2. **掛け合い**: 「ミク！」の掛け声はフレーズの切れ目に置く。歌が問い、プレイヤーが答える。
3. **完成体が歌詞を纏う**: 背景に並んだミクの周りを、その体を作ったときの歌詞が回る。
   曲終わりのギャラリーは、**曲全体の歌詞が並んだ光景**になる。

---

## 7. リザルト（曲の終わり）

背景に並んだ全ミクがカーテンコール。ボーカル音量に合わせて一斉に揺れる。

```
     [炊飯器ミク] [ネギミク] [ポストミク] [ハゲた消火器]  ← 今日の成果
              総スコア 18,420  /  最大コンボ 14
                   「ミクだらけ！」
```

- 失敗作（ハゲ）も並ぶ。**そこが一番笑える**。
- 1 枚絵としてスクリーンショットしたくなる構図にする（会場の一般投票対策）。

## 8. 追加提案（v2 で新規に足す遊び）

順に検討し、採否を決めた。

| # | 案 | 判定 | 理由 |
| --- | --- | --- | --- |
| 1 | **スライド方向で髪型が変わる**（下＝ストレート／外＝広がり／上＝跳ね） | **採用** | タイミングは課題、形は自由。**同じ曲でも人によって違うミクができる**。方向は判定に使わないので目押し不要のまま |
| 2 | **ステレオ定位で左右を指示** | **採用** | 原則 A の実装。ヘッドホンで化ける |
| 3 | **コンボで背景のミクが合いの手** | **採用** | 音楽的報酬。上手いほど曲が厚くなる＝リズム天国の「ノリ」 |
| 4 | **カウントイン（3・4）** | **採用** | 初見で入れる。教える設計 |
| 5 | **ハゲのまま背景に並ぶ** | **採用** | 失敗の笑い。リプレイ動機 |
| 6 | オブジェクトごとに固有リズム | 見送り | 覚える負荷が高く、リズム天国の「1 ゲーム 1 リズム」原則に反する |
| 7 | 長押しで髪を伸ばし続ける | 見送り | 拍から外れる自由入力は原則 B に反する |
| 8 | 対戦・オンラインランキング | 見送り | 応募規模を超える。将来案 |
| 9 | **観賞モード**（無操作時に自動演奏） | **採用** | コンテスト要件。手が勝手に打つ様子自体が見て面白い |

### お題オブジェクト（見立てが強いもの）
ネギ（ミクの定番ミーム）／ペットボトル／炊飯器／マグカップ／信号機／
招き猫／郵便ポスト／消火器／目覚まし時計／掃除機／自販機／ドアノブ

シルエットが特徴的で、**髪をつけた瞬間に化ける**ことが選定基準。

## 9. 技術方針（枯れた技術の水平思考）

| 技術 | 本来の用途 | 転用 |
| --- | --- | --- |
| `StereoPannerNode` | 音像定位 | **左右どちらを打つかの指示**（目押し封じ） |
| WebAudio の先読みスケジューラ | シーケンサ | 合図音を数十 ms 先に予約して精度を出す |
| Web Speech API | 読み上げ支援 | **「ミク！」の掛け声**（ライセンス回避＋機械音声のユーモア） |
| Canvas 2D のみ | — | 全端末で確実に動く。WebGL 不使用 |
| ノイズ + バンドパス | 効果音の基礎 | シャキーン（金属質）／シャラララー（星） |

依存は `textalive-app-api` のみ。ビルドは Vite。
