# 設計書: ミクの本体はツインテールである

## 1. コンセプト

> あらゆる造形物は、ツインテールを正しく生やせばミクになる。
> そしてツインテールは、ミクの歌声からしか生えない。

プレイヤーは楽曲再生中、画面中央の「まったく別の造形物」（黄色いホイール、炊飯器、信号機……）に
ドラッグでツインテールを 2 本描き足していく。描けるのは**ミクが歌っている瞬間だけ**。
歌詞の文字が髪の毛としてストロークに流れ込み、ビートに合った入力だけが髪を定着させ、
ボーカル音量が髪を揺らす。サビで「**ミク度**」が採点され、曲が終わると
その曲で作った全作品（ミク化した造形物たち）のギャラリーが流れる。

### 出落ち回避の構造（本企画の核）

視覚ギャグ「何でもミクに見える」は 1 回で消費される。これを防ぐ装置は 3 層:

| 層 | 装置 | 音楽データとの結線 |
| --- | --- | --- |
| 素材 | 髪の毛＝**歌詞の文字** | 文字の発声タイミング（`IChar`）でしか髪は供給されない |
| 操作 | 描画判定＝**ビート** | 拍に乗ったストロークだけが定着（リズムゲームの骨格） |
| 演出 | 髪の揺れ＝**ボーカル音量** | 声が強いほど髪がなびく＝「声が身体を動かす」の可視化 |

この結線により、ゲームの結論はタイトルの逆説の反転になる:
**「ミクの本体はツインテールである。ただしそのツインテールは歌声でできている」**。
バカゲーとして笑わせたあと、リリックアプリとしての主題（歌声・歌詞の可視化）に着地する。

## 3. ゲームフロー（楽曲構造への写像）

1 プレイ＝ 1 曲。TextAlive のセクション情報で進行が駆動され、操作説明なしで遊べる密度にする。

```
イントロ      お題抽選: 造形物がステージにせり上がる（valence/arousal で抽選テーブルが変わる）
              例: 明るい曲 → ホイール・じょうろ / 静かな曲 → 街灯・湯呑み
Aメロ/Bメロ   髪集めパート: 発声中の歌詞文字が造形物の周囲に漂う。
              ビートに合わせてドラッグすると文字がストロークに吸着し、髪として定着。
              拍を外すと文字は霧散（減点はしない。焦りではなく笑いを誘う挙動: 文字が「え…」と落下）
間奏          結い直しタイム: アンカー（つむじ位置）の移動、左右の付け替えのみ可能。声がないので髪は生えない
サビ          ミク度判定: 造形物がライブ照明を浴び、採点式（§5）が走る。
              スコアと称号を大写し（「ミク度 94% ─ もはや本人」「ミク度 31% ─ それはただの炊飯器」）
2番以降       お題交換: 新しい造形物が登場し再装填。前の作品は背景のギャラリー棚に並ぶ
アウトロ      カーテンコール: 今日ミク化した造形物たちが全員でライブの手振り（ボーカル音量で揺れる）
```

- 曲のセクション数だけお題が回転する＝ WarioWare 型の再装填。1 曲で 3〜5 体作る。
- リザルト画面は「棚に並んだミクたち」1 枚絵。スクリーンショット→SNS 共有導線（一般投票対策）。

## 4. 操作系

- **入力はポインタ 1 本のみ**（マウス／タッチ共通）。ドラッグ＝髪ストローク、タップ＝アンカー移動。
- ストロークは 2 本まで。3 本目を描くと古い方が「散髪」される（迷いなく描き直せる）。
- 誤操作で詰む状態を作らない: 髪は何度でも描き直せる、採点はサビ時点のスナップショット。

## 5. ミク度採点（枯れた技術による幾何採点）

ML を使わない。全項目が中学幾何＋古典アルゴリズムで、挙動が説明可能・調整可能・軽量。

| 項目 | 配点 | 算法 |
| --- | --- | --- |
| 対称性 | 30 | 右ストロークを造形物の中心軸で鏡映し、左ストロークと**リサンプリング後の平均点間距離**で比較（ポリライン 32 点等間隔リサンプル。離散フレシェ距離の簡易版） |
| つむじ位置 | 20 | 2 つのアンカーが造形物バウンディングボックスの上部 1/4・左右対称位置にあるか（正規化座標の距離） |
| 長さ比 | 20 | 髪長 ÷ 造形物の高さ。理想値 1.6（ミクの身長比ツインテールに由来する「黄金比」としてネタ化） |
| ハリ・ツヤ | 20 | 定着した文字のうち**ビート適合入力**だった割合（リズム精度が髪の輝きシェーダ強度にもなる） |
| 歌詞充填率 | 10 | その曲で発声された文字数のうち髪に取り込めた割合（聴き込み・周回プレイの報酬） |

- 対称性・つむじ・長さは「見た目のミクらしさ」、ハリツヤ・充填率は「音楽との同期度」。
  **視覚ギャグ点と音楽ゲーム点が同一スコアに合流する**のが採点設計の要点。
- 称号テーブル（例）: 0–29「無機物」/ 30–59「ミク味を感じる」/ 60–84「親戚」/ 85–100「もはや本人」。
  低得点も面白い絵になるよう、称号は必ず笑いに変換する。

## 6. TextAlive App API 活用マップ

| API | 用途 | 備考 |
| --- | --- | --- |
| `IChar`（文字単位タイミング） | 髪素材の射出 | 発声と同時に文字がポップ |
| `findBeat(position)` | ストローク定着判定 | 判定窓は ±(拍長 × 0.25) を初期値にチューニング |
| `findChorus(position)` | ミク度判定の発火 | サビ検出が無い曲はセクション末尾で代替発火 |
| `findChord(position)` | 髪のグラデーション変化 | コードチェンジで色相を微回転 |
| `getVocalAmplitude(position)` | 髪の風力（揺れ） | `vocalAmplitudeEnabled: true` |
| `getValenceArousal(position)` | お題抽選・背景ムード | `valenceArousalEnabled: true` |
| セクション情報 | ゲームフロー進行 | §3 の写像 |

## 7. 観賞モード（コンテスト要件対応）

TextAlive ホスト埋め込み時・無操作時も楽曲同期演出として成立させる:

- 一定時間無操作なら「見えざる手」（白手袋のカーソル）が登場し、模範的なツインテールを
  ビートに合わせて描いてみせる（＝チュートリアルを兼ねた自動デモ）。
- シーク・一時停止はすべて `position` 起点の純関数的描画で追従（内部状態は
  「定着済みストローク＋定着時刻」のみ。時刻より未来の髪は描かない）。

## 8. 枯れた技術の水平思考（技術方針）

新技術を足すのではなく、確立済みの安い技術を「別の遊び」に転用する:

| 枯れた技術 | 本来の用途 | 水平思考での転用 |
| --- | --- | --- |
| Verlet 積分ロープ（90 年代ゲーム物理） | 鎖・布 | ツインテール物理。剛性低めの 20 節ロープ 2 本。風力＝ボーカル音量 |
| ポリラインのリサンプリングと鏡映比較（古典 CG） | 手書き認識の前処理 | ミク度の対称性採点。$1 Recognizer 系の考え方の流用 |
| パーティクル吸着（スチーム時代の演出技法） | 集約エフェクト | 歌詞文字→ストローク吸着の気持ちよさ |
| Canvas 2D のみ（WebGL 不使用） | — | 会場のどの端末・審査環境でも確実に動く。依存ゼロ、単一バンドル |
| テンプレート見立て（福笑い） | 伝統玩具 | ゲームデザインそのものの原型。「福笑い×リズム」と一言で説明できる |

方針: **依存ライブラリは textalive-app-api のみ**。ビルドは Vite、描画は Canvas 2D、
物理・採点・パーティクルはすべて自前 300 行級の古典実装。
（このリポジトリの [prototype/index.html](../prototype/index.html) が物理と採点の実証。依存なし単体 HTML で動作）

## 9. リスクと対策

| リスク | 対策 |
| --- | --- |
| 「描くゲーム」は無操作審査で伝わらない | §7 観賞モードを一級市民として実装。デモの手が笑いも担う |
| ネタの権利面（絵本・ミームの直接引用） | 絵本やミーム画像は引用しない。「見立て」という構造だけを使い、造形物は自作のオリジナル雑貨に限定 |
| 曲ごとの尺・構造差でフロー破綻 | セクション写像は相対制（セクション数で正規化）。サビ検出欠落時のフォールバックを仕様化（§6） |
| 採点が理不尽に感じられる | 採点内訳をレーダーチャートで開示。全項目が幾何なので「なぜその点か」を絵で説明できる |
| タッチ端末での描き心地 | ストローク簡略化（Ramer–Douglas–Peucker、これも枯れた技術）で入力ゆらぎを吸収 |
