# 市場調査

企画「ミクの本体はツインテールである」の前提となる調査。2026-08-30 時点。

## 1. コンテストの現状

- マジカルミライのプログラミング・コンテストは [TextAlive App API](https://developer.textalive.jp/) を使い、楽曲コンテスト受賞曲（例年 5〜6 曲）に合わせて歌詞などの映像演出が動く「リリックアプリ」を募集する形式。2026 年で 6 回目。
- 2026 年大会は 2026-08-28 に[受賞作品が発表済み](https://www.crypton.co.jp/cfm/news/2026/08/28mm26procon)。**本企画のターゲットは次回（2027 年大会、例年 4 月頃募集開始〜7 月締切）**。
- 入選作品は会場の企画展モニターで上映され、来場者アプリ「ミクナビ」での**一般投票**がある（[2025 年アフターレポート](https://blog.piapro.net/2025/09/ms2509121.html)）。
  - → 審査員向けの技術点だけでなく、**「会場で 10 秒眺めただけで伝わる」瞬発力**が明確に効く評価構造。バカゲーの出落ち力は、ここでは欠点ではなく武器。
- 応募要件上、アプリは TextAlive のホストに埋め込まれ、**ユーザーが操作しなくても楽曲に同期した演出が成立すること**が求められる（シーク対応・自動再生対応）。→ ゲームであっても「観賞モード」が必須（DESIGN.md §7）。

### 過去応募作の傾向と空白地帯

過去の入選作・公開作の大勢は「歌詞タイポグラフィ＋背景演出」系のビジュアライザで、
インタラクティブなゲーム型は毎年少数派。さらに「笑い」を主軸に据えた作品はほぼ空白。

| 象限 | 既存作品の密度 | 本企画 |
| --- | --- | --- |
| 観賞型 × シリアス（美麗リリックビデオ） | 激戦区 | — |
| 観賞型 × ユーモア | 少ない | 観賞モードで参入 |
| ゲーム型 × シリアス（リズムゲーム的） | 少数の常連枠 | — |
| **ゲーム型 × ユーモア（バカゲー）** | **ほぼ空白** | **主戦場** |

## 2. 類似ゲームの調査（何が出落ちを防いでいるか）

「一発ネタを遊びとして持続させた」先行例の分解:

| 作品 | 一発ネタ | 持続させた仕組み | 本企画への転用 |
| --- | --- | --- | --- |
| [Quick, Draw!](https://www.itmedia.co.jp/news/articles/2212/03/news034.html)（Google） | AI が落書きを当てる | 20 秒の時間制約＋お題の連続＋他人の絵の提示 | 制約は「時間」でなく**楽曲構造**（ビート・ボーカル区間）から与える |
| AutoDraw（Google） | 落書きが清書される | 認識結果の即時フィードバック | ミク度をリアルタイム表示せず**サビまで隠す**ことで逆張り（結果発表の緊張） |
| QWOP / Getting Over It | 操作が異常に難しい | 失敗自体が絵として面白い | 失敗作（ミク度 12% のホイール）も**スクショしたくなる絵**として成立させる |
| Untitled Goose Game | ガチョウが迷惑 | ネタを支える堅実なシステム（TODO リスト） | ギャグを支える採点システムを幾何学で堅実に作る（DESIGN.md §5） |
| WarioWare 系 | 瞬間バカゲーの連打 | 1 ネタ 5 秒で回転させ飽きさせない | 曲のセクションごとにお題（造形物）を交換し 1 曲＝ショート連作にする |

共通解: **一発ネタの「発射台」を別システム（制約・採点・連作化）が何度も再装填している**。
本企画では再装填装置が「楽曲そのもの」になる——これが音楽ゲームとしての固有性。

## 3. 文化的文脈（このネタは今、公式的に「あり」か）

- たなかひかる著の公式絵本[『わたし初音ミク こまっているの』](https://blog.piapro.net/2026/06/ni26061501.html)（2026-06-26 発売）は、ミクのチャームポイントであるツインテールを軸にシュールな展開をする内容で、[出版社内から「これ公式が OK 出したんですか？」と戸惑いの声が出た](https://natalie.mu/music/news/676530)ことも含めて話題化した。
  - → 「ミクっぽさを記号として突き放して笑う」表現を、**クリプトン公式が直近で許容・成功させた**実績。企画の時流適合性は高い。
- 「黄色いホイール＋緑ホース＝ミク」型のネットミームは、ミクが**色と形の最小記号で成立するキャラクター**であることの民間実証。ネギ（Ievan Polkka 以来の公式化したミーム）と同じく、二次創作文化が「見立て」を歓迎してきた土壌がある。
- キャラクター消費論の観点でも、ミクは「設定より記号の組合せで愛されるデータベース型キャラクター」の代表例とされ、記号の分解・再構成そのものを遊びにする本企画はミク文化の本質に触れるテーマ性を持つ（＝バカゲーの皮を被った批評、として審査員向けの語り口も立つ）。

## 4. 技術基盤の確認（TextAlive App API で何が取れるか）

[公式ドキュメント](https://developer.textalive.jp/app/song/)・[Player API リファレンス](https://developer.textalive.jp/packages/textalive-app-api/classes/Player.html)より:

| データ | API | 本企画での用途 |
| --- | --- | --- |
| 歌詞（フレーズ／単語／文字単位の発声タイミング） | `IPhrase` / `IWord` / `IChar` | 文字を「髪の毛」として射出 |
| ビート | `findBeat()` 等 | 描画入力の判定タイミング、髪の定着 |
| コード進行 | `findChord()` | 髪の色調（ツヤ）の変化 |
| サビ・繰り返し区間 | `findChorus()` 等 | ミク度判定イベントの発火 |
| ボーカル音量 | `getVocalAmplitude()`（`vocalAmplitudeEnabled`） | 髪の揺れの強さ＝「声が髪を動かす」 |
| 感情値 (valence/arousal) | `getValenceArousal()`（`valenceArousalEnabled`） | お題（造形物）の抽選テーブルと背景ムード |

ゲームに必要な入力データはすべて公式 API のみで賄え、外部 ML・外部音声解析は不要。

## 5. 結論

1. **ポジション**: ゲーム型×ユーモアはコンテスト内でほぼ空白。一般投票という評価構造とも噛み合う。
2. **時流**: 公式絵本がツインテール・シュールネタを直近で公認しており、企画の受容リスクは低い。
3. **持続性**: 先行バカゲー分析より「発射台の再装填」が鍵。再装填装置を楽曲構造（セクション・ビート・声）に担わせることで、視覚ギャグと音楽データが不可分になる。
4. **実現性**: 必要データは TextAlive App API 標準機能で完結。採点も古典幾何で足りる（DESIGN.md）。
